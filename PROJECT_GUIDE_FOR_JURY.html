🎯 3. Problem Statement & Real-World Context

Why is this software needed by banks, governments, and corporations?

  • Alert Fatigue: A typical bank receives 10,000 to 50,000 alerts daily. Analysts cannot keep up and get burned out.
  • Schema Fragmentation: Splunk, IBM QRadar, firewalls, and AWS CloudTrail all output logs in completely different formats. Correlating them takes hours.
  • Executive Communication Gap: When an intrusion happens, CISOs and executives need a BLUF brief (What was hit? What is the impact? What do we do right now?). Compiling this manually wastes valuable incident response time.
  • False Positives: Over 80% of alerts are isolated pings or harmless errors. Finding the coordinated campaign inside the noise is like finding a needle in a haystack.

🔄 5. The 7-Step Pipeline (From Raw Logs to Solution)

1
Ingestion & Validation

User uploads security CSV log. System verifies required columns (timestamp, src_ip, dst_ip, event, severity), cleans whitespace, and inserts rows into PostgreSQL under the user's tenant ID.

2
Temporal Correlation

Sorts alerts by time. Groups alerts sharing the same source IP. If the gap between two events exceeds 30 minutes, it splits them into separate Attack Chains.

3
MITRE ATT&CK Alignment

Maps event signatures to standardized Enterprise MITRE techniques (e.g. PortScan → T1595 Reconnaissance, CredentialDumping → T1003 Credential Access).

4
Deterministic Risk Scoring

Evaluates the mathematical formula: Event Score + MITRE Score + Chain Bonus. Assigns severity: Low (0-25), Medium (26-50), High (51-75), Critical (76-100).

5
LangGraph AI Agents Execution

LangGraph triggers Recommendation Agent to formulate 4-category containment guides, then triggers the BLUF Report Agent to formulate the executive summary.

6
Vector Knowledge Sync (Qdrant)

FastEmbed model (bge-small-en-v1.5) generates 384-dimensional embeddings of the attack narrative and indexes them in Qdrant Vector Database with metadata filters.

7
SOC Dashboard & AI Copilot

Data renders on the React SOC dashboard with live charts, and analysts can ask questions in the AI chat with grounded responses and cited IPs.

🧮 6. Exact Risk Scoring Math & Formula

When the jury asks "Show me your mathematical formula for risk", show them this:

Total Score = Event Score + MITRE Tactic Score + Chain Bonus (Capped at 100)

Component 1: Event Score (Sum of unique observed attack types)

  • Data Exfiltration: 70 pts
  • Ransomware: 60 pts
  • Malware: 50 pts
  • Privilege Escalation: 45 pts
  • Lateral Movement / Credential Dumping: 40 pts
  • Command Execution / C2 Beacon: 35 pts
  • SQL Injection: 30 pts
  • Brute Force / DDoS: 25 pts
  • Port Scan / Reconnaissance: 10 pts

Component 2: MITRE Tactic Score (Deduplicated tactics)

  • Exfiltration: 30 pts | Impact: 25 pts
  • Credential Access / Privilege Escalation / Lateral Movement: 20 pts each
  • Execution / Persistence / Defense Evasion / Command & Control: 15 pts each
  • Initial Access: 10 pts | Reconnaissance: 5 pts

Component 3: Chain Progression Bonus (Attack Maturity)

  • 7 or more attack events: +20 points bonus
  • 5 to 6 attack events: +15 points bonus
  • 3 to 4 attack events: +10 points bonus
  • Fewer than 3 events: 0 bonus

Severity Classification:

CRITICAL (76 - 100)  |  HIGH (51 - 75)  |  MEDIUM (26 - 50)  |  LOW (0 - 25)

🎯 8. Top 15 Jury Questions & Winning Answers

Q1: "Why didn't you just feed all raw logs directly to ChatGPT or Llama?"
Answer: "Feeding raw logs directly to an LLM fails for three big reasons:
1. Token Limits & Cost: 10,000 logs exceed context windows and cost too much.
2. Hallucination: An LLM can hallucinate IP addresses and generate arbitrary, non-reproducible risk numbers.
3. Regulatory Auditability: Cybersecurity frameworks like NIST and ISO require identical logs to produce identical scores every single time.
That is why we use a hybrid architecture: deterministic Python math handles correlation, MITRE mapping, and scoring, while the LLM is reserved for what it does best: human summarization, executive briefs, and interactive analyst chat."
Q2: "What is LangGraph and why did you pick it over regular LangChain?"
Answer: "Regular LangChain chains are strictly linear. If step 2 fails, the whole program crashes. LangGraph allows us to build a stateful directed graph with conditional edges. If any node encounters an issue, our should_continue router catches it and gracefully short-circuits to store_results, logging the error in the database instead of crashing."
Q3: "How does your correlation prevent false positives?"
Answer: "False positives are usually isolated, one-off alerts like a single failed login or random port ping. Our correlation engine groups alerts by source IP within 30-minute windows and sorts them along the cyber kill-chain. An isolated ping stays a low-risk, single-event chain. Only coordinated, multi-stage intrusions earn chain bonuses and get escalated to Critical."
Q4: "What is BLUF and why does an executive need it?"
Answer: "BLUF stands for Bottom Line Up Front. In a cyber incident, a Chief Information Security Officer (CISO) does not have time to read 50 pages of firewall logs. They need to know three things in under 60 seconds: What happened? What is the business impact? What decision must I make right now? Our BLUF Report Agent synthesizes this in a crisp, sub-100-word brief."
Q5: "How do you protect data between different users or client companies?"
Answer: "We enforce multi-tenant isolation at four layers:
1. Database Foreign Keys: Every table has a user_id with cascade delete.
2. Composite Indexing: (user_id, chain_id) ensures Tenant A's AC001 never collides with Tenant B's AC001.
3. Strict SQLAlchemy Filters: Every database query includes filter(Model.user_id == current_user.id).
4. Tenant-Prefixed Cache Keys: Redis keys look like stats_{user_id}, preventing cross-tenant data leaks."
Q6: "Why did you use Qdrant and FastEmbed instead of OpenAI?"
Answer: "Three reasons:
1. Privacy: FastEmbed runs locally using ONNX runtime, meaning internal confidential IP addresses never leave the server.
2. Speed: Embeddings are calculated in <15 milliseconds with zero external API calls.
3. Metadata Filtering: Qdrant allows instant vector filtering by user_id and risk_level at query time without degrading search quality."
Q7: "How many automated tests do you have?"
Answer: "We have 106 automated tests written in Pytest across 10 test files in src/backend/tests/, validating our CSV parser, correlation engine, MITRE mapper, risk math, LangGraph short-circuiting, and RAG chat."
Q8: "What are your known limitations?"
Answer: "We are completely transparent about our current scope:
1. Currently processes batches via CSV/JSON uploads up to 50MB; real-time Kafka streaming is scheduled for version 2.
2. Correlation primarily anchors on source IP; distributed multi-IP botnets currently map as separate chains until merged at the destination layer.
3. If cloud LLM keys are absent in air-gapped environments, the system falls back to rule-grounded heuristic templates."
